# E0101: ambiguous term reference

## Summary

A term reference inside a `verify` block (or a `claim secret(...)`)
matches more than one binding site, and Clementine cannot determine
which one you mean.

## Why this matters

Per Clementine design step 1 §1.4, every term reference in a
`verify` block must resolve to a unique binding. An ambiguous
reference would silently resolve to *one* of the candidates, and the
resulting lemma would be quietly proving (or failing to prove) a
claim about a different term than the one the user intended. This
is the most common cause of vacuously-true secrecy lemmas in
hand-written Tamarin theories.

## Example

```clem
step m1 : A -> B { new k; send ENC(<...>, k) }
step m2 : C -> D { new k; send ENC(<...>, k) }    // <-- same name 'k'

verify {
  secrecy(k)    // E0101: which 'k'?
}
```

## Fix

Qualify the reference. Three forms are accepted, in order of
preference:

* `principal@step.var` — fully qualified, e.g. `A@m1.k`
* `step.var` — only when the step label is unique across principals,
  e.g. `m1.k`
* `var` — only when there is exactly one binding for the name across
  the whole protocol

Alternatively, rename one of the bindings so each name is unique.
