# E0209: honest peer unreachable for agreement lemma

## Summary

An `injective_agreement(I, R, ...)` (or `non_injective_agreement`)
query references roles `I` and `R`, but the rule graph contains no
trace in which both `I` and `R` are honest. The lemma would be
vacuously true.

## Why this matters

Lowe-style agreement lemmas have the standard form:

```
Commit @ i  ==>  (Ex Running @ j & j < i)
              | (Ex Reveal & Honest @ i)
```

If the rule graph never reaches a state where both `I` and `R` are
registered honest agents (no `Reveal_Ltk_*` for either), then
`Commit @ i` is itself unreachable, and the lemma trivially holds
because the antecedent is unsatisfiable.

This is invariant 9 of the Clementine soundness invariants
(design step 3 §3.4). The compiler refuses to emit a lemma it can
prove vacuous from the rule graph alone.

## Common cause

Forgetting to register one of the principals, or having a
`knows public pkB` declaration without a corresponding
`principal B { generates skB; ... }` block to populate `!Pk`.

## Example

```clem
principal A {
  generates    skA
  knows public pkB              // pkB is not registered by anyone
}

verify {
  injective_agreement(A, B, [k])  // E0209: B has no Register rule
}
```

## Fix

Either add a `principal B { generates skB; ... }` block or use
`knows public pkB from network` to allow B to be adversary-supplied
(which weakens the lemma but lets you express UKS-style attacks).
