# E0401: open chain has no honest origin

## Summary

The sources lemma inference detected an open chain: a fresh value
that arrives at some `In(...)` premise inside an envelope different
from any envelope it was ever sent in. But the heuristic could not
identify *any* honest rule that could have produced the value, so
the auto-generated sources lemma would be unprovable.

## Why this matters

Clementine emits sources lemmas annotated `[sources]`, which means
Tamarin proves them inductively *before* using them. A wrong
sources lemma fails loudly rather than silently licensing bogus
proofs (Clementine design step 5 §5.6 — this is exactly the
soundness escape valve). But a sources lemma that *cannot be proved*
will hang the entire proof effort, so the compiler would rather
refuse to emit it.

Reaching this error usually means one of:

1. The fresh value is exclusively adversary-derived in the model
   (i.e., it appears only in `KU` chains), and you should remove the
   sources obligation by suppressing it with `@no-sources` on the
   receive site.
2. The fresh value's "honest origin" is inside a `raw {}` block
   that the chain detector cannot see into — add an explicit
   `@source` annotation on the originating rule.
3. The protocol has a type-flaw bug (real bug in the model).

## Fix

Read the source location in the diagnostic, identify the receive
site, and decide which of the three causes applies. The compiler
will not auto-pick.
